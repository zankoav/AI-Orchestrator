# Orchestrator

Локальный Kanban-оркестр, управляемый Codex через Markdown-инструкции и задачи по расписанию. В `backlog` живут идеи, а в `work` — только карточки, одобренные реальным владельцем продукта `po-human`.

В первой версии нет Python-процессов, API-ключей и интеграции с Jira. Источник правды — файл `kanban-state.json`.

## Правила работы

1. Каждая роль сначала читает `ORCHESTRA.md`, затем свою инструкцию из `agents/` и только потом `kanban-state.json`.
2. Исполнитель работает лишь с карточками, назначенными ему в поле `assignee`.
3. Исполнитель добавляет результат исключительно в `comments`. Он не меняет `status` и `assignee`.
4. Только `pm-dispatcher` может менять статус и ответственного — и всегда фиксирует причину отдельным комментарием.
5. Не использовать клиентские или персональные данные в демонстрационных карточках.

## Первый ручной запуск

В чате Codex открой эту папку и напиши, например:

> Выполни роль BA Analyst: прочитай `ORCHESTRA.md`, `agents/ba-analyst.md` и `kanban-state.json`. Обработай только назначенные BA карточки, добавь один структурированный комментарий с результатом. Не меняй `status` и `assignee`.

Проверь результат в `kanban-state.json`. После удачного ручного запуска можно попросить Codex создать повторяющиеся Scheduled Tasks — по одной для каждой роли.

Для локальных файлов во время запуска по расписанию компьютер и приложение Codex должны быть запущены. [Официальная инструкция OpenAI](https://developers.openai.com/training/walkthroughs/scheduled-tasks)
